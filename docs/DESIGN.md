# AX 타입 테스트 설계

## 논지

"AI 시대에 나는 어떤 일꾼인가"는 지금 일하는 사람 누구나 한 번쯤 던지는 질문이고, 답이 **정체성 한 줄**로 떨어지면 사람들은 그걸 올린다. 이 테스트는 그 한 줄을 1분 안에 주고, 올리기까지의 마찰을 0에 가깝게 만든다.

기준 틀은 Claude Code 를 만든 Boris Cherny 의 다섯 아키타입이다 ([원문](https://x.com/bcherny/status/2071379474277613732)). 그의 정의를 그대로 옮기면:

| 타입 | 원문 요지 |
|---|---|
| Prototyper | 완전히 새로운 아이디어를 낸다. 많이 만들고, 대부분은 출시되지 않는다 |
| Builder | 프로토타입이나 아이디어를 빠르게 프로덕션급 제품·인프라로 만든다 |
| Sweeper | UI 를 정리하고, 코드와 시스템을 단순화하고, 기능을 내리고, 성능을 최적화한다 |
| Grower | 만들어진 제품을 반복 개선해 제품-시장 적합도를 높인다 |
| Maintainer | 성숙한 시스템을 맡아 규모가 커져도 안전하고, 안정적이고, 빠르고, 효율적이게 유지한다 |

그가 덧붙인 두 가지가 설계의 뼈대다. **직군과 무관하다** (디자이너도 PM 도 데이터 과학자도 각 타입에 흩어져 있다) → 문항은 직군 중립적인 장면으로 쓴다. **많은 사람이 두세 타입에 걸친다** → 결과는 메인 + 서브를 같이 준다.

## 대상

Threads 에서 일·개발·AI 이야기를 하는 사람. 스크롤 중에 친구의 결과 카드를 보고, 링크를 누르고, 1분 뒤 자기 카드를 올린다. 이 루프가 한 바퀴 도는 데 드는 총 시간이 3분을 넘지 않아야 한다.

## 바이럴 루프

세 가지 정체성 훅 중 최소 둘을 맞춘다. (근거: 퀴즈 공유 동기는 열망·인정·소속으로 나뉘고, 강한 퀴즈는 그중 둘을 친다 — 조사 요약은 `findings.md`)

| 훅 | 여기서의 구현 |
|---|---|
| 인정 "이거 나잖아" | 결과 문구는 행동 장면으로 쓴다: "회의 중에 이미 데모를 만들고 있는 사람". 성격 형용사가 아니라 동료가 알아볼 장면 |
| 열망 "이렇게 보이고 싶다" | 다섯 타입 모두 칭찬 언어. 약점은 "조심할 것"으로만, 그것도 강점의 그림자로 |
| 소속 "너는 뭐야?" | 케미 섹션(최고의 짝 / 부딪히지만 필요한 짝)이 태그할 사람을 만든다. 공유 문구 끝이 질문("당신은?") |

루프의 각 단계와 마찰 제거:

1. **보기** — Threads 피드에 링크 미리보기(OG 이미지)가 뜬다. 타입별 `og/<type>.png` 1200×630 에 이모지·이름·한 줄이 크게. 텍스트만 있는 게시물보다 카드가 눈에 걸린다.
2. **누르기** — `r/<type>/` 는 OG 태그만 들고 본편(`?r=<type>`)으로 보낸다. 받은 사람은 친구의 타입 설명을 먼저 보고, 바로 아래 "나도 테스트하기 (1분)". 랜딩 페이지를 거치지 않는다.
3. **풀기** — 10문항, 3지선다, 한 화면에 한 문항, 진행 바. 되돌아가기 가능. 이름·이메일 안 묻는다 (사전 게이트는 공유율을 죽인다).
4. **결과** — 스크롤 없이 첫 화면에 카드 + Threads 버튼. 공유 문구는 미리 채워져 있다 (타입 이름, 한 줄, 서브 타입, 링크, 해시태그). 버튼 하나로 작성창까지.
5. **올리기** — Threads 웹 인텐트 `threads.com/intent/post?text=`. 링크가 본문에 있으면 Threads 가 미리보기를 붙인다 (이미지를 같이 올리면 미리보기는 빠진다). 이미지로 올리고 싶은 사람을 위해 "이미지로 저장"(1080×1350, 4:5). X 는 보조 링크.

의도적으로 뺀 것: 이메일 수집, 로그인, 결과 저장, 분석 스크립트, "상위 N%" 같은 근거 없는 희소성 문구, 광고. 각각 왜 뺐는지는 `findings.md` 의 기각 목록.

## 문항 원칙

- **10문항.** 완주율과 판별력의 타협점. 자료마다 권장이 다르다. 한쪽은 완주율 변곡점을 7~8문항 부근으로 보고, 다른 쪽은 성격 유형 퀴즈에 13문항을 권한다. 10 은 그 사이이고, 3지선다에서 5타입을 primary 6회씩 정확히 배분할 수 있는 수이기도 하다.
- **장면 기반, 직군 중립.** "당신은 창의적입니까?" 가 아니라 "월요일 아침, AI 에이전트에게 제일 먼저 시키는 일은?". 자기 보고 편향을 줄이고, 디자이너·PM·개발자가 다 답할 수 있게.
- **정답 없음, 다 매력적.** 세 선택지가 모두 "그럴 만한" 사람의 말로 읽혀야 한다. 한 선택지가 뻔히 좋아 보이면 문항이 망가진 것.
- **AI 는 배경, 패턴이 주제.** AI 를 직접 묻는 문항은 둘(1번, 5번)이다. 나머지 여덟은 AI 가 있든 없든 성립하는 일의 장면이다. 결과가 '도구 사용 습관'이 아니라 '일하는 패턴'을 가리키게 하려는 선택이고, 원문의 아키타입도 도구가 아니라 패턴을 말한다. AI 는 결과 문구("AI 시대, 당신의 무기")에서 다섯 타입 모두에 붙는다.
- **마지막 문항은 열망.** "1년 뒤 어떤 말을 듣고 싶나". 문항이 장면에서 바람으로 끝나야 결과 화면의 정체성 언어로 자연스럽게 이어진다.

## 채점

각 선택지는 primary 타입 +2, secondary 타입 +1. 30개 선택지에서 모든 타입이 primary 6회, secondary 6회 — `scripts/check.mjs` 가 강제한다. 한 문항마다 3점이 배분되므로 총점은 항상 30이고, 결과 화면의 다섯 막대는 그 30점을 나눠 가진 비율이라 합이 100% 다.

동점 규칙, 순서대로: 총점 → primary 로 고른 횟수 → 더 나중 문항에서 primary 로 고른 쪽(뒤쪽 답일수록 앞 문항들을 거친 뒤의 선택이라는 가정) → 수명주기 순서(프로토타이퍼 → 메인테이너). 결정적이고, 같은 답이면 항상 같은 결과.

서브 타입은 2위.

## 정직성 게이트

이 테스트의 "검증"은 스스로를 확인하는 구조가 되기 쉽다 (설계자가 곧 채점자). 그래서 밖에서 들어오는 기준을 둔다:

- **분포 게이트.** 3^10 = 59,049 개 답 조합 전부를 돌려 어떤 타입도 12% 아래로 내려가지 않는지 확인한다. 다섯 타입이 고르면 20% 씩이고, 12% 는 그 60% 선으로 잡은 임계값이다. 특정 타입이 나오기 어렵게 문항이 기울면 실패. 이 게이트는 채점의 기울기만 잡는다. 어떤 선택지가 사회적으로 더 '좋아 보여서' 사람들이 몰리는 편향은 못 잡으므로, 그건 문항 원칙(정답 없음)과 콜드 리드로 본다.
- **문구 게이트.** 근거 없는 수치("N% 만 이 타입")를 쓰지 않는다. 출처가 있는 사실(아키타입 정의)은 링크로 출처를 단다.
- **명시.** 랜딩·결과 화면과 README 에 "재미로 보는 테스트"를 적는다. 심리측정 도구가 아니다. 표준 성격검사는 대개 수십 문항이고, 문항이 늘수록 신뢰도가 오른다.
- **콜드 리드.** 배포 전에 이 작업을 보지 않은 별도 리뷰어(paperthin 의 `shower` 스킬: 맥락 없는 새 세션에 결과물만 넘겨 읽게 한다)가 문서와 문구를 읽고 막히는 곳, 스스로 세운 규칙과 어긋나는 곳을 찾는다. 찾은 것은 고치고, 왜 그랬는지는 `findings.md` 에 남긴다.

## 결과 문구 규칙

각 타입은 같은 뼈대를 가진다. 뼈대가 같아야 카드가 나란히 놓여도 비교가 된다.

| 필드 | 길이 | 역할 |
|---|---|---|
| headline | ≤ 16자 | "~하는 사람". 카드와 OG 의 큰 글씨. 공유의 핵심 |
| tagline | 한 문장 | 타입의 세계관. "당신에게 ~는 ~입니다" |
| traits ×3 | 각 한 줄 | 동료가 알아볼 장면. 형용사 금지 |
| weapon | 두 문장 | AI 가 이 타입을 어떻게 증폭하는가. 반드시 AI 언급 |
| shadow | 한 문장 | 강점의 그림자. 비난 아님 |
| best / clash | 타입 + 한 줄 | 소속 훅. clash 는 "부딪히지만 필요한 짝"으로 프레임 |
| share | 한 줄 | 공유 문구용 압축판 |

## 파일

한 사실은 한 곳에: `data.js` 가 타입·문항·공유 문구의 유일한 집. `scoring.js` 가 채점의 유일한 집. `r/` 와 `og/` 는 `scripts/build.mjs` 의 생성물이고 `scripts/check.mjs` 가 원본과의 어긋남을 잡는다. 프레임워크·번들러·의존성 없음. 사이트는 정적 파일 다섯 개(`index.html`, `app.js`, `style.css`, `data.js`, `scoring.js`)로 돈다.

배포 주소는 `SITE.url` 한 곳에 끝 슬래시 없이 적는다. 크롤러가 읽는 OG 절대 경로는 여기서 나오고, 사람이 보는 공유 링크는 실행 중인 주소(`location`)에서 계산한다. 그래서 로컬에서 띄운 화면의 공유 문구에는 로컬 주소가 들어간다. 정상이다.
